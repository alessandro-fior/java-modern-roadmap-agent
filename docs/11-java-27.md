# 11 — Java 27

**Release non-LTS.** GA il 15 settembre 2026. Sei mesi di supporto.

Attenzione a questo punto, perché è la confusione più comune: **Java 27 non è LTS.**
Java 25 lo è. La prossima LTS sarà **Java 29**, prevista per settembre 2027.

Per un progetto in produzione la scelta prevedibile resta Java 25. Java 27 è
interessante per capire dove sta andando la piattaforma, non come base di un rilascio.

---

## I nove JEP

Java 27 è la release con il set più piccolo dal JDK 20: nove JEP, di cui cinque ancora
in preview o incubazione.

| # | JEP | Titolo | Stato |
|---|---|---|---|
| 1 | [523](https://openjdk.org/jeps/523) | Make G1 the Default Garbage Collector in All Environments | definitivo |
| 2 | [527](https://openjdk.org/jeps/527) | Post-Quantum Hybrid Key Exchange for TLS 1.3 | definitivo |
| 3 | [531](https://openjdk.org/jeps/531) | Lazy Constants (Third Preview) | **preview** |
| 4 | [532](https://openjdk.org/jeps/532) | Primitive Types in Patterns, instanceof, and switch (Fifth Preview) | **preview** |
| 5 | [533](https://openjdk.org/jeps/533) | Structured Concurrency (Seventh Preview) | **preview** |
| 6 | [534](https://openjdk.org/jeps/534) | Compact Object Headers by Default | definitivo |
| 7 | [536](https://openjdk.org/jeps/536) | JFR In-Process Data Redaction | definitivo |
| 8 | [537](https://openjdk.org/jeps/537) | Vector API (Twelfth Incubator) | **incubator** |
| 9 | [538](https://openjdk.org/jeps/538) | PEM Encodings of Cryptographic Objects (Third Preview) | **preview** |

Le quattro definitive e che cambiano il comportamento senza toccare il codice sono
523, 527, 534 e 536. Le altre cinque sono esempi, isolati in
[`examples/java27/`](../examples/java27/README.md).

## Le definitive

### JEP 523 — G1 predefinito ovunque

In Java 27 G1 è il garbage collector predefinito **in tutti gli ambienti**, anche su
macchine con un solo processore o con molta memoria, dove prima era richiesto specificarlo.

```bash
java -Xlog:gc -cp target/classes it.example.modernjava.customeranalyzer.CustomerAnalyzer
```

Non è un cambiamento di codice: è un cambio di default. Se hai benchmark storici,
**rifalli**: il collector è diverso da quello che avevi misurato.

### JEP 527 — TLS ibrido post-quantum

La negoziazione chiave ibrida (post-quantum + classica) è **attiva per default**. Non
serve cambiare codice: client e server concordano un segreto ibrido, quindi la connessione
resta protetta anche se una delle due parti viene intercettata in futuro.

```bash
java examples/java27/TlsPostQuantumDemo.java
```

Per disattivarla:

```bash
java -Djdk.tls.namedGroups=X25519:secp256r1 ...
```

**Nota operativa importante:** le chiavi post-quantum ML-KEM generate con JDK 27 sono
codificate in PKCS#8 con il formato `SEED` per default e **non** sono riconosciute dalle
versioni precedenti. Se passi chiavi tra versioni diverse, imposta:

```bash
java -Djdk.mlkem.pkcs8.encoding=EXPAND_AND_ROUND ...
# oppure
java -Djdk.mlkem.pkcs8.encoding=EXPANDED ...
```

Gli algoritmi X25519 e Ed25519 sono anche più veloci in Java 27.

### JEP 534 — Compact Object Headers

L'intestazione di ogni oggetto scende a **8 byte** (era 12 o 16). Con milioni di oggetti
vivi il risparmio è reale, e di solito si accompagna a un miglioramento della cache
locality.

```bash
java examples/java27/ObjectHeadersDemo.java
```

### JEP 536 — JFR In-Process Data Redaction

Le registrazioni del JDK Flight Recorder nascondono automaticamente valori sensibili
(chiavi, password, token). Si controlla con:

```bash
java -XX:FlightRecorderOptions:redact-key=true \
     -XX:FlightRecorderOptions:redact-argument=true ...
```

## Le preview

Una preview è un'API **non garantita**: cambia (o sparisce) nelle release successive, e
richiede `--enable-preview` in compilazione ed esecuzione.

```bash
javac --release 27 --enable-preview Esempio.java
java  --enable-preview Esempio
```

Le classi compilate con preview girano **solo** su una JVM identica: niente deploy su
un'altra versione.

### JEP 531 — Lazy Constants

Valori immutati inizializzati al primo accesso, non nel costruttore:

```java
private static final LazyConstant<Logger> LOG =
        LazyConstant.of(() -> Logger.create(OrderController.class));

void submitOrder(User user) {
    LOG.get().info("order started");
}
```

A differenza di un campo non-`final` nullable, garantisce che il valore sia calcolato
**una e una sola volta** anche con più thread, e resta eleggibile per il constant folding.

Ci sono anche `List.ofLazy(...)`, `Map.ofLazy(...)` e `Set.ofLazy(...)`.

Terza preview: nel passaggio da 25 a 27 il nome è cambiato (`StableValue` →
`LazyConstant`) e sono spariti metodi (`orElseSet`, `setOrThrow`, `trySet`,
`isInitialized`, `orElse`). In JDK 28 dovrebbe essere definitivo.

### JEP 532 — Pattern su tipi primitivi

Estende `instanceof` e `switch` a `int`, `long`, `double`, `boolean` e ai loro wrapper:

```java
switch (o) {
    case int n -> "un intero: " + n;
    case String s -> "una stringa: " + s;
    default -> "altro";
}
```

Quinta preview. Utilissima, ma non è ancora qualcosa su cui scrivere codice di produzione.

### JEP 533 — Structured Concurrency

Trattata già nel capitolo sui Virtual Threads. In JDK 27 è alla settima preview e l'API
è cambiata di nuovo: tre parametri di tipo su `StructuredTaskScope`, costruttori pubblici
sostituiti da factory statiche, `awaitAll()` rimosso, `onTimeout()` diventato `timeout()`.

JEP 543 (Candidate) dovrebbe finalizzarla in JDK 28 "senza ulteriori modifiche".

### JEP 538 — PEM Encodings of Cryptographic Objects

API per codificare e decodificare chiavi, certificati e CRL nel formato PEM. Terza
preview, e si ferma un giro: una patch tardiva ha rimesso il suffisso "Preview", quindi
la finalizzazione slitta a JDK 28.

## L'incubatore

### JEP 537 — Vector API

Dodicesima incubazione. Permette di scrivere calcoli vettoriali in Java puro che il JIT
compila in istruzioni SIMD native (AVX, NEON, SVE). Nessun cambiamento sostanziale
rispetto a JDK 25, a parte la libreria SLEEF aggiornata per ARM e RISC-V.

Il modello di adozione è "scrivi Java, ottieni codice nativo". Però: la maturità è ancora
lontana dalla maturità di un'API stabile.

## Le altre modifiche rilevanti

Non sono JEP, ma nelle note di rilascio:

- `HttpServer` passa dal prefisso di stringa al prefisso di percorso (cambio di
  comportamento)
- `ThreadPoolExecutor.finalize()` rimosso
- Rimosso `java.locale.useOldISOCodes`
- Rimossa l'interfaccia JVMCI
- Supporto per le ultime codifiche di chiavi private ML-KEM e ML-DSA in PKCS#8
- Compressione dei certificati TLS con zlib (RFC 8879) attiva per default
- `VecMap` deprecato in `java.util.function`

## Cosa fare in pratica

| Se vuoi... | Allora |
|---|---|
| restare su una base stabile | resta su **Java 25** (LTS) |
| capire il futuro della piattaforma | leggi i JEP, non adottarli |
| sperimentare in un branch separato | `--enable-preview` su una JDK 27 dedicata |
| evitare sorprese sui default | rifai i benchmark dopo l'upgrade |

## Esercizio

1. Installa una JDK 27 e confronta i tempi di `GcDefaultsDemo` con `-XX:+UseG1GC`
   esplicito e senza.
2. Sui tuoi stessi dati, prova `ObjectHeadersDemo` con e senza
   `-XX:+UnlockExperimentalVMOptions -XX:+UseCompactObjectHeaders`.
3. Leggi il JEP 533 e prova a descrivere in tre righe che cosa cambia per un server web
   che oggi usa `ExecutorService` e `Future`.
